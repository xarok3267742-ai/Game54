# Release Report

## Выбранная идея

`Порядок 5`: offline-first Android-приложение с микрозадачами на 3, 5 и 10 минут для русскоязычной аудитории.

## Реализовано

- Native Android project from scratch.
- Compose UI: onboarding, home, task details with non-duplicated step structure, timer, result, progress, settings/privacy/about.
- Onboarding copy is aligned with the actual first-run controls: the first screen asks only for a starting area, while energy and duration are introduced on Home in “Настроить подбор”.
- Home flow is quick-task-first: the suggested task, non-interactive task status, selection-quality hint, compact result preview and launch actions appear before aligned “выполнено/серия/каталог” metrics and a collapsed filter disclosure summary, reducing friction and making fallback suggestions transparent.
- Home primary and secondary task actions now use decorative Material vector icons while keeping Russian text labels as the accessible names.
- Main-flow CTA icons are now consistent across onboarding, task details, timer completion, result next/repeat actions and progress return, without adding `material-icons-extended`.
- Compact header and back controls use vector icons with Russian accessibility labels instead of text glyph icons; Home “Итоги” uses a dedicated `StatsIcon` instead of a completion checkmark.
- Home includes a `Другая задача` action that skips the current suggestion without recording progress; the engine excludes skipped ids while alternatives exist, falls back cleanly when the matching pool is exhausted, and explains the disabled state with `Других задач по этому подбору сейчас нет`.
- Area, energy and duration filter chips expose selected/unselected accessibility state in Russian, not only visual border/background changes.
- Local JSON task catalog with 80 original Russian tasks.
- DataStore persistence for onboarding, settings and progress.
- DataStore reads recover from local `IOException` with defaults, normalize corrupted negative progress counters, malformed last done dates and blank/whitespace completed ids for UI, and completion progress is calculated inside the DataStore edit transaction.
- Progress writes normalize negative counters, malformed last done dates and blank/whitespace completed ids before storage, while blank completion submissions do not increment totals or streaks.
- Settings enum raw values are trimmed before fallback, so whitespace-corrupted preferred-area state restores correctly instead of silently falling back to Home.
- MainActivity collects the DataStore preferences flow with `collectAsStateWithLifecycle`, backed by an automated gate that rejects lifecycle-unaware startup state collection.
- Runtime task catalog parsing is strict for blank ids, route-unsafe ids, duplicate ids, id/area mismatches, unknown area/energy values, unsupported durations, blank title/result text and malformed steps, uses shared domain validators for task ids and duration validation, and keeps launch errors generic Russian UI text.
- Startup catalog load errors now use a full-screen retry state with generic Russian copy and `Повторить загрузку`, avoiding a dead-end technical error.
- Loading states now use a full-screen centered spinner and message for catalog/progress startup waits.
- Suggestion engine unit tests cover exact-match selection, relaxed fallback, whole-catalog fallback, next-task exclusion, completed-id trimming and progress counts that ignore unknown stored ids.
- Wall-clock timer behavior for pause/resume/background catch-up.
- Timer expired state disables the impossible pause/resume action and labels it `Время вышло`, leaving reset/completion as the clear next actions.
- Timer, catalog and per-area progress bars use shared `ProgressLine` visuals with accessibility semantics and no false end-dot marker on zero-progress rows.
- Timer shows the compact `После` expected-result preview under the active step list, so the user can keep the finish criterion visible while the countdown is running.
- Timer completion action is guarded against rapid double submit for the current task and stays pinned in a bottom action dock so `Готово` remains reachable on compact screens.
- Result flow displays aligned “выполнено/серия/каталог” metrics and the next-task preview with compact `После` outcome before repeating, excludes the just-completed task when another exact or same-area/same-duration task exists, and switches to a completed-catalog repeat state when no fresh tasks remain.
- Result next-task preview uses details-first primary action `Посмотреть следующую`, while `Запустить таймер` remains a secondary shortcut, so the user can inspect the upcoming task and its expected result before starting another timer.
- Task status now uses `TaskStatusPill` with a small dot indicator instead of a bordered filled chip, so `новая`, `повтор` and `выполнено` read as status, not tappable controls.
- Catalog progress percent and unique completed count ignore unknown stored task ids.
- Progress and about screens read the catalog size from `PoryadokEngine`, so runtime UI cannot drift from the loaded task catalog count.
- Progress screen shows total completions, streak, numeric catalog percent, neutral completed-catalog copy and per-area completion counts with progress bars, using normalized known completed ids from the engine. It also includes a compact `Серия` / `Счётчик` rhythm summary and “Продолжить с задачей” so users can understand progress rules and return to the active task flow without relying on Back.
- PoryadokEngine normalizes completed ids before suggestions and progress counts, so whitespace-corrupted ids cannot cause immediate repeats or undercounted progress.
- Task duration filters are normalized to the supported 3/5/10-minute set before UI suggestions and engine matching, so corrupted restored duration state falls back to 5 minutes instead of bypassing exact matching.
- System Back navigation on internal screens returns to the expected app context instead of unexpectedly closing the app.
- Current internal screen state is saveable across Activity recreation, including task-bound details/timer/result routes; corrupted task-bound routes fall back to Home unless the task id matches the shared route-safe catalog id shape.
- Centered max-width layout constraints for main content and top bars on large viewports.
- Settings screen includes an “О приложении” block with compact `Версия`, `Каталог` and `Данные` facts, using `BuildConfig.VERSION_NAME` and the runtime catalog size.
- Settings privacy card uses unframed `PrivacyBadgeGrid` facts with short explanations (`работает офлайн`, `вход не нужен`, `нет баннеров`, `нет трекеров`), keeping the local-only/no-ads/no-analytics model visible at a glance without nested cards.
- Settings haptics toggle uses a full-row 56dp+ switch target, so the user can tap the label area instead of only the small switch control.
- Settings reset flow uses two-step confirmation, an explicit cancel path, guarded `DangerAction` styling for the final destructive action and inline completion feedback after progress is cleared.
- Play Store and launcher icons were refreshed to a friendlier ImageGen-derived checklist/timer/check composition without heavy dark task dots; the same source now generates the 512x512 Play icon and Android raster launcher density assets through a reproducible local generator.

- Upload keystore: не создаётся и не хранится в проекте.
- Final Google Play feature graphic approval: ImageGen candidate exists, but still needs final preview approval before production upload.
- Analytics/crash reporting: намеренно не добавлены для privacy/simple MVP.
